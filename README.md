# Daily Demand Forecasting

An explainable forecasting case study: linear trend and weekday effects, chronological evaluation, a seasonal-naive baseline and calibration residual bands. Built by **Arwa Ahmed** as an independent portfolio demonstration, not client work.

## Run in two commands

Requires Python 3.10+; no pip packages, GPU, accounts or network access.

```sh
python -m unittest -v
python forecast.py --output artifacts
```

The CLI writes `report.json`, `model.json` and `predictions.csv`. Checked-in `examples/` files were generated by `python forecast.py --output examples` with seed 17. Re-run rather than treating their numbers as an external benchmark. To evaluate your own data:

```sh
python forecast.py --csv daily-demand.csv --test-days 28 --output artifacts/custom
```

CSV columns are `date,demand`; dates must be ordered, daily and gap-free, demand finite and nonnegative. Missing days are rejected so an undocumented imputation policy cannot silently change the problem. Invalid inputs return a nonzero process exit.

## Design and evaluation

- The default generator produces 196 invented days with a trend, weekly pattern and seeded Gaussian noise. No customer data or downloaded dataset is used.
- The first 140 days fit an eight-parameter OLS model. The next 28 calibrate absolute residual bands. The final 28 are untouched test observations.
- A partial-pivot linear solver fits the small design matrix. Time is scaled in weeks, and one weekday is omitted to avoid a redundant intercept.
- Test forecasts are made without reading test targets. The seasonal-naive baseline repeats the final observed week, including the calibration window; it has more recent observations than the frozen model.
- MAE/RMSE and observed interval coverage are reported. The bands are heuristic for dependent temporal data: a nominal level is not a guaranteed coverage claim.

Tests check exact recovery of a noiseless known process, target leakage, calibration isolation, missing dates, invalid values and seasonal-naive behavior. Comments explain numeric scaling, frozen fitting and baseline information boundaries.

## Practical limits

This is a transparent baseline, not inventory optimization or a production demand model. There are no promotions, holidays, stockouts, hierarchy, structural breaks or probabilistic count likelihoods. Synthetic data deliberately resembles the chosen model and therefore cannot establish superiority on real data. Negative predictions are clipped to zero, which can bias low-volume forecasts. Real deployment needs rolling-origin evaluation, realistic data, monitoring and business-specific cost metrics. See [MODEL_CARD.md](MODEL_CARD.md).
